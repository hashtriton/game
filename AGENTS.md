# Инструкции для Codex в game

Эти инструкции действуют в существующем проекте `C:\Users\Netes\Desktop\proj\game` и его подкаталогах. Перед работой прочитайте применимые инструкции из родительских `AGENTS.md`, локальные `.agents/skills` и более узкие инструкции в затрагиваемых подкаталогах. Существующие пользовательские файлы дополняйте аккуратно; не заменяйте их целиком без необходимости.

Релевантные локальные Codex memories можно читать через доступный `memory_summary.md`. Не читайте запрещённые каталоги сессий и не используйте их для поиска контекста.

## Область и способ работы

- Работайте только над `game`. Сначала установите точный путь, состояние файлов и Git. Не создавайте дубликат проекта, не меняйте другие проекты, production, чужие настройки MCP или общие настройки без необходимости.
- Текущий этап использует Unity и Blender. Не возвращайтесь к выбору между Unity и Godot без нового поручения пользователя.
- Основной способ разработки и настройки - код, CLI, API и MCP. UI используйте для необходимой настройки, входа владельца и проверки, если это требуется инструментом. Не стройте игру ручными кликами по редактору.
- Допустимы инициализация локального Git в изолированной папке, минимальный пустой Unity 3D проект и нейтральные проверки Unity/Blender. Это не разрешение реализовывать всю игру или окончательно выбирать дизайн.
- Прежде чем писать игровой код, прочитайте `docs/context.md`, `docs/decisions.md` и фактический статус в `docs/setup.md`.

## Разрешения и настройки

- Пользователь разрешил необходимую настройку и обычные официальные установки. Не запрашивайте повторное разрешение на уже разрешённые обратимые действия.
- Новые явные юридические соглашения, вход в аккаунт, создание постоянных credentials, расширение чувствительного доступа и изменения security требуют соответствующего подтверждения владельца.
- Не устанавливайте стороннее ПО неизвестного происхождения без подтверждения конкретного действия в момент установки. Проверяйте официальный источник и происхождение загрузки.
- Не покупайте подписки. Не создавайте удалённый репозиторий, не публикуйте проект, не выполняйте коммерческий релиз и не отправляйте сообщения другим людям без отдельного разрешения.
- MCP используйте локально. Не открывайте публичный порт. Привязывайте локальный сервер к loopback, если протокол требует сетевого транспорта; предпочитайте stdio, если он официально поддерживается выбранным инструментом.
- Общую конфигурацию меняйте минимально, с резервной копией. Не затрагивайте чужие MCP-серверы. По возможности применяйте конфигурацию только к этому проекту и фиксируйте область её действия.
- Не выводите секреты, токены, cookies или credentials в логи, документы и ответы; не коммитьте их. Записывайте только безопасные сведения о наличии авторизации и результаты проверки.
- Официальный BlenderLab MCP может выполнять Python без sandbox. До включения такого исполнения оцените необходимые локальные разрешения и изоляцию. Если действие меняет security или расширяет чувствительный доступ, получите подтверждение владельца; не превращайте разрешение на обычную установку в разрешение на неограниченный доступ к ПК.
- Не обходите HTTP 403 или другие ограничения доступа. При блокере укажите точное действие, адрес/программу, риск и минимальное требуемое подтверждение; продолжайте независимую подготовку.

## Контекст и права

- Данные в `docs/research.md` - переданные результаты прежнего исследования, если прямо не сказано иное. Не представляйте их как собственную свежую проверку. Новые локальные карты Warcraft 3.4/3.9c и Dota snapshot находятся в `.local/research/lia/`; отчеты и производные выгрузки - в `docs/lia-*.md` и `research/lia/`.
- Перед использованием LiA для игрового кода прочитайте [правила работы с данными](docs/lia-data-use.md), [результат ревью](docs/lia-review.md) и [сводку механик](docs/lia-mechanics-balance.md). Вход в каталоги: [research/lia/README.md](research/lia/README.md).
- Проверяйте актуальность проверенного набора командой `py -3 -X utf8 tools/research/lia_validate.py`. На ПК без оригиналов доступна только проверка сохраненных исследовательских файлов: `py -3 -X utf8 tools/research/lia_snapshot.py --repository-only`. Ее успех не подтверждает оригиналы, парсеры или матчевое поведение на этом ПК.
- Для заимствуемого правила фиксируйте версию/hash, ID, source path/line или byte offset, условия применения и уровень доказательства. `declaration`, `static-path` и `derived` не равны `runtime`. Конфликты profiles, binary overrides, inherited defaults и динамические ветки нельзя молча разрешать удобным значением из плоского CSV. Изменение проверенных файлов требует повторной проверки и обновления ревью, а не одного перезаписывания snapshot.
- Не переносите чужие код, карты, модели, текстуры, звуки, названия персонажей и брендинг в нашу игру без проверки прав. Отсутствие общей LICENSE в исследованном репозитории не даёт разрешения на использование его содержимого.
- Не смешивайте Warcraft 3.4 с 3.9c и не приравнивайте статические определения KV/JASS к фактическому поведению опубликованной игры.
- Не выводите размер покупателей, MAU, средний CCU или продажи из дневных пиков и записей лобби. Не прогнозируйте конверсию аудитории кастомок без данных.
- Отсутствие бюджета на платное продвижение не означает нулевой бюджет разработки. Steam/Windows, itch.io, MVP, сеть и монетизация ещё не утверждены.

## Проверка и запись результатов

- Используйте актуальные официальные источники при настройке. Обязательные ссылки: [замена старого Unity MCP на Unity CLI](https://docs.unity.com/en-us/unity-cli/replace-mcp-server-unity-cli), [Unity CLI](https://unity.com/blog/meet-the-unity-cli), [BlenderLab MCP](https://www.blender.org/lab/mcp-server/), [BlenderLab](https://www.blender.org/lab/).
- Проверьте версии Unity Editor, Unity CLI/Pipeline, Blender и Codex, а также наличие действующего Unity аккаунта/лицензии безопасным способом. Устанавливаемость, отсутствие ошибок конфигурации и существование аккаунта - разные проверки.
- Не объявляйте инструменты подключёнными по одному конфигу. Проверьте клиент-сервер и реальную простую операцию из Codex. Для Unity подтвердите открытие проекта и компиляцию; для Blender - простую сцену, сохранение и экспорт.
- Отличайте ограничения текущего исполнителя от настройки для следующей пользовательской сессии. Repo-scoped MCP, записанный в файле, может ещё не быть доступен активному агенту. Запишите, что именно было реально вызвано, через какой транспорт и каким клиентом.
- В `docs/setup.md` фиксируйте дату, команды/операции, версии, результаты, безопасные пути к логам и оставшиеся блокеры. Указывайте отдельно подтверждённые и непроверенные операции. Не заменяйте неудачную проверку предположением.
- Проверки держите нейтральными и минимальными: локальный пустой проект, примитивная сцена, экспорт тестового объекта. Не включайте чужие ассеты или дизайн всей игры.
- После изменений проверьте целостность документов, ссылки внутри репозитория, состояние Git и отсутствие секретов/ненужных сгенерированных файлов. Unity `Library`, `Temp`, `Logs` и локальные кеши не включайте в Git.
