# Ревью данных Life in Arena перед сохранением в Git

Дата: 2026-10-05. По отдельному поручению пользователя проведено повторное независимое ревью Dota, Warcraft и парсеров. Значения сопоставлены с оригиналами, контрпримеры устранены, исправления проверены другим агентом.

**Результат:** набор пригоден как проверяемая статическая исследовательская база в пределах описанного покрытия. Это не утвержденная спецификация собственной игры и не сертификат фактического игрового баланса. Условия использования закреплены в [lia-data-use.md](lia-data-use.md) и корневом `AGENTS.md`.

## Найдено и исправлено

| Проблема первоначального набора | Исправление и проверка |
| --- | --- |
| Binary overrides сравнивались вместе с offsets; реальные изменения высоких уровней не попадали в balance CSV | Сравнение rawcode/field/level/pointer/type/value. Неизменный `A0HG.Ilif=-100` исключен из diff при переносе записи; `A001.Istr` level10/pointer3 `30 -> 20` включен. Оба случая проверены по оригинальным `.w3a`, затем независимым расчетом по всему diff |
| Повторные profile keys/sections теряли предыдущие значения | Сохранены все `_assignments` с точными строками, реестры повторов и межфайловых конфликтов. В каждой карте 6 повторов, 3 меняют значение; cross-file conflicts 4/5. Все 25 287/34 582 raw profile assignments независимо сверены с JSON и CSV |
| Regex индекса JASS принимал текст подсказок за вызовы | Маска строк и комментариев всего script с сохранением новых строк; keywords исключены. Контрпример `Справке (Alt+H)` больше не создает вызов. Независимая маска дала тот же граф, номера функций и исходные строки не сдвинулись |
| Dota replay перезаписывал эталон, мог пропускать новые файлы и не отличал skipped от verified | Генерация в пустой временный каталог, сравнение точных наборов и SHA256, проверка неизменности эталона. Ошибка subprocess, missing/extra/changed и пустой output дают FAIL. `not_run` не объявляется подтвержденной воспроизводимостью |
| Старые validation flags могли пережить изменение данных | Fingerprint документов, скриптов, derived outputs, оригиналов и локальных parser dependencies. Modified/missing/extra фиксируются; отдельно проверяется точный набор распакованных Dota files. Snapshot подтверждает неизменность рассмотренных байтов, а не правильность любой игровой логики |
| Порядок `misc_changes` зависел от hash seed Python | Ключи отсортированы. Три version-diff файла побайтово совпали при seeds 1 и 777 |
| Два текстовых уточнения могли исказить будущую реализацию | Выбор сложности 3.4 подписан `ZQ`, а не локальным именем `Xs`. В Clan XP 3.9c убийца/герой владельца призыва добавляется до добора остальных героев в радиусе 1300 |
| Происхождение JSON/CSV могло быть понято неверно | Явно указано наличие производных сторонних данных, tooltips и фрагментов JASS/Lua. Хранение в исследовательском каталоге не разрешает перенос чужого кода/контента в игру |

После исправления version diff содержит 19 223 различия явных представлений: 17 502 обычных поля и 1 721 binary override. В balance CSV 6 131 кандидат, включая все 286 числовых binary изменений. SLK и binary не сведены в недоказанную итоговую runtime-модель.

## Независимо проверенное содержание

- Dota: все 456 строк экономики, 50 строк XP/бонусов атрибутов, 24 строки setters боссов; сумма lumber 1..19 равна 262. Проверены вызовы, различие alive/hidden/reincarnating и момент измерения участников.
- Dota: все 66 рецептов отдельным разбором raw KV, цены компонентов/свитков/результатов, повторные ингредиенты, 134 узла деревьев и все 9 расхождений объявленной стоимости.
- Dota: Battle Axe, regen globals/API, damage filter и матрица, modifiers босса 15, фазы финала 70/30%, поздние штрафы, дуэльные награды и cooldown paths. Значимых ошибок в этих исходных выводах не обнаружено.
- Warcraft: raw JASS подтвердил 62/96 начальных героев, 76/101 рецептов и 244/337 ребер. Проверены core-формулы волн, сложности, экономики, XP, уровней и фаз Орна. Независимый SYLK-разбор подтвердил поля босса и несоответствие сохраненных derived min/max его dice-полям.
- Warcraft: все profile assignments и связи source line, function boundaries, numeric/operation/global line references; 1 994/3 271 функций на 44 321/87 360 строках. Gameplay-файлы MPQ проверены двумя читателями, оригиналы сохранены с SHA256.

## Повторяемость и актуальность

24 regression tests покрывают выявленные дефекты, отрицательные сценарии validator/snapshot и сохранность эталонов. Изолированно воспроизведены 50 Dota-артефактов, 90 Warcraft-артефактов и 4 core-файла; missing/extra/modified отсутствуют. Сами кастомки не запускались.

Команды проверки из корня проекта:

```powershell
py -3 -X utf8 -m unittest discover -s tools/research -p '*test*.py'
py -3 -X utf8 tools/research/dota_validate.py --reproduce
py -3 -X utf8 tools/research/lia_reproduce.py
py -3 -X utf8 tools/research/lia_validate.py
```

Результаты: [Dota validation](../research/lia/dota2/validation.json), [Warcraft/core replay](../research/lia/review/reproduction.json), [общая проверка](../research/lia/validation-summary.json), [проверенные хеши](../research/lia/review/reviewed-snapshot.json). `.gitattributes` сохраняет точные байты исследовательских файлов при Git checkout, включая окончания строк CSV.

`lia_validate.py --prepare-review` проверяет извлечение до записи нового fingerprint и явно оставляет `review_snapshot_verified=false`. Этот режим не заменяет обычную проверку. После независимого ревью и успешных replay допускается `lia_snapshot.py --write`, затем обязательно обычный `lia_validate.py`. На другом ПК `--repository-only` проверяет только сохраненную часть; это более узкое доказательство.

## Остаток, который не считать закрытым

Не проверены реальные матчи, патчевые defaults Warcraft/Dota, округление и stacking движка, соответствие Dota GitHub реальному Workshop package, полный динамический граф тысяч abilities/triggers/секретов, баланс по результатам матчей. Приоритет конфликтующих profiles явно не установлен. Три синтаксически ошибочных Lua-файла остаются свойством оригинального snapshot; статическая недостижимость не доказывает невозможность любой динамической загрузки.

Эти ограничения не мешают хранить исследование и использовать подтвержденные значения как исходную точку. Они требуют отдельных проверок перед превращением неопределенного эффекта в обязательное поведение собственной игры. Обнаруженные дефекты исходной кастомки не следует автоматически воспроизводить как желательный дизайн.
